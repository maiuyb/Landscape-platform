# 统一个人作品管理

按用户确认完成“统一自己的作品管理”。“可复用配方”标识及其相关展示暂不处理。

## 使用入口

- 个人主页的“管理作品”进入统一工作区；用户中心侧栏将“我的上传”改为“我的作品”，不再单列重复的上传记录入口。
- 工作区提供“已发布作品”“发布记录”“删除找回”三个分区。已发布作品沿用卡片／画廊偏好，两种模式都能查看、删除作品。
- 发布记录展示发布时间、发布／删除状态及删除时间；尚在公开展示的作品可直接进入详情。
- 删除找回只展示本人的已删除作品，按删除时间倒序排列。7 天内提供找回按钮，过期记录仅展示状态，沿用现有服务端找回限制。
- 卡片、画廊、记录与详情共用删除确认，说明删除后不再公开展示以及“我的作品 → 删除找回”的恢复入口。
- 删除与找回保留当前页；当前页已不存在时回到最后一个有效页。取消删除不发送写请求；操作期间避免对同一作品重复发起删除／找回。
- 列表失败可原位重试，手机端分区按钮与记录内容自动换行；个人主页、收藏、账号与个性化设置继续沿用。

## 接口与数据

`GET /api/me/uploads` 保持原有完整记录返回语义。新增可选 `status=deleted`，在服务器按当前登录用户筛选已删除作品后，再计算总数及分页；未知筛选返回 400，未登录仍返回 401。该参数不开放到公开作品接口。

无 schema 变更、数据迁移、素材处理或社区数据导入。删除仍为软删除，找回期限仍为 7 天，既有账号、作品、图片和收藏保留。

## 验证

- `tests/work-management-browser.cjs`：根路径和 `/landscape` 的统一入口、三个分区、取消删除、卡片／画廊／详情删除、删除／找回后的分页、恢复公开可见性、仅本人记录、失败重试、320–1440 布局及个人主页返回。使用临时数据库、合成账号及图片。
- `tests/profile-api-check.py`：8 项资料／账号与接口测试，含本人的删除筛选、完整记录兼容、筛选后分页、过期不可找回、他人不可恢复及找回后公开列表一致性。
- `tests/user-center-browser.cjs`、`tests/author-portfolio-browser.cjs`、`tests/community-main-compatibility-browser.cjs`：根路径与子路径相关回归。
- 截图和报告保存在本机忽略目录 `test-results/work-management/`。线上仅匿名读取健康接口、静态资源和公开页面，不登录用户账号，不执行删除、恢复或发布。
