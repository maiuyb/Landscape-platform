## 修复记录

### #1 社区页卡顿（2026-10-21）

**原因**
- 卡片/推荐/详情都直接加载上传原图：8 张共 40 MB，最大 9984×6656，而卡片只显示 242px
- `loading="lazy"` 对首屏 8 张基本无效；推荐区与网格重复解码
- 顶栏 `backdrop-filter: blur(16px)` 在滚动时持续重算模糊
- 图片缺 `srcset` / `width` / `height` / `decoding="async"`

**改动**
- 后端 `backend/app.py`
  - 新增 `build_thumbnail()`：Pillow 生成 WebP（质量 82），宽度 200/400/800/1200
  - 新增 `GET /api/thumb/<filename>?w=400`，按需生成并缓存到 `uploads/.thumbs/`
  - 上传 `/api/upload` 时预生成 400/800 两档，响应增加 `thumb`
  - 缩略图响应加 `Cache-Control: public, max-age=31536000, immutable`
  - 文件名白名单 + 路径穿越校验；EXIF 方向修正；最大像素放宽到 2 亿
- 前端 `frontend/community/app.js`
  - 新增 `thumbUrl()` / `thumbSrcset()`
  - 卡片、推荐位、上传记录改用缩略图，并加 `srcset`、`sizes`、`width/height`、`decoding="async"`
  - 详情弹窗仍使用原图（大图查看）
- 前端 `frontend/community/style.css`
  - 顶栏移除 `backdrop-filter: blur(16px)`，改为 0.98 不透明暖白；弹窗模糊保留

**实测（Playwright，1440×1000）**
| 指标 | 优化前 | 优化后 |
|---|---:|---:|
| 首屏图片流量 | 40 MB | **0.12 MB** |
| 卡片解码宽度 | 4000–9984px | **360–400px** |
| 卡片显示宽度 | 242px | 242px |
| 详情图 | 原图 | 原图（保持） |
| 390px 横向溢出 | 无 | 无 |

- 现有 10 张图已预热 40 个缩略图（`uploads/.thumbs/`）
- 服务已重启，改动即时生效

### #3 编辑器放大后无法拖动查看（2026-10-21）

**现象**
- 画布缩放到 200%/400% 后，图片超出可视范围，但按住图片拖动不会移动画面，只能靠滚动条。

**改动**
- `frontend/app.js`
  - 新增 `startPan` / `movePan` / `endPan`：在 `.canvas-container` 上按住左键拖动，调整 `scrollLeft/scrollTop`
  - 仅在图片确实溢出（`scrollWidth/Height > clientWidth/Height`）时启用
  - 排除裁剪、拉直、透视、蒙版、白平衡取样、细节查看和导出锁定状态
  - 拖动超过 4px 才判定为平移，避免误触；拖动后 350ms 内忽略 `stageClick`
  - 监听缩放/预览尺寸变化，切换 `can-pan` 光标
- `frontend/index.html`
  - `.canvas-container` 增加 `pointerdown / pointermove / pointerup / pointercancel / lostpointercapture`
- `frontend/style.css`
  - `.canvas-container.can-pan { cursor: grab; touch-action: none; }`
  - `.canvas-container.panning { cursor: grabbing; user-select: none; }`

**验证（Playwright）**
- 100%：`scrollWidth=1096 = clientWidth`，`can-pan=false`，`cursor=auto`
- 400%：`scrollWidth=4086 > clientWidth=1096`，`can-pan=true`，`cursor=grab`
