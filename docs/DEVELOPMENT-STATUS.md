## 3. 可逆的实现决定

- 保留 Vue / Flask / SQLite 技术路线，使用原生控件组织核心工作区，移除前端运行对 Element Plus 和外部 CDN 的依赖。Vue 版本通过 `package-lock.json` 固定，安装时复制运行文件与许可证到被忽略的 `frontend/vendor/`。
- `frontend/editor-core.js` 提供纯状态/配方模型与统一 Canvas 渲染。历史只存参数和构图，不为每一步保存大图。工作预览源图最长边上限 1200 像素；导出从原图按所选比例重建。
- 裁剪坐标使用 `unit: normalized`，便于预览和原尺寸导出共用。旧配方里的绝对像素裁剪因坐标依据不明确而忽略，并给出提示；旧版七类调色、滤镜、旋转、翻转仍能读取。
- 配方预览更新配方明确列出的调色/滤镜项，保留未列出的项，构图操作按顺序追加；导入完整 JSON 配方包含所有参数，所以可以重建中性值和滤镜强度。
- 编辑项目只在当前页面内存中保存。刷新或关闭页面后不恢复，页面明确告知；有修改时启用浏览器离页提示。配方文件不含原图，可主动下载。
- PNG 保留自由旋转空白区域的透明度，JPG 用白色填充；界面有说明。浏览器只能确认已生成文件并发起下载，提示不声称文件必然已保存到磁盘。
- 前端/API 同源，默认保留 5000 端口并支持 `PORT` 覆盖；本机 5000 已被其他服务占用，本轮预览使用 5050。
- 没有改动原型的账号接口、生产服务器配置或后端上传大小限制；登录、投稿与“我的配方”不作为本轮核心工作区入口展示，按当前 PRD 的后续范围处理。

## 7. 接续补修：后端上传大小限制

2026-10-10 用户明确要求修复此项，替代交接包及 D-15 的原暂挂决定。

- `/api/upload` 单张文件上限为 20 × 1024 × 1024 字节，与前端一致。检查已解析文件流的实际长度，不依赖文件声明的大小；恰好等于上限可以上传。
- 解析上传表单前，限制该请求最大 21MiB，其中 1MiB 预留给 multipart 边界、字段及其他表单开销。只作用于上传接口；AI 和社区 JSON 接口未套用这个请求上限。
- 超限统一返回 JSON 格式的 HTTP 413，提示“上传文件或请求过大，单张图片最大 20MB，请重新选择图片。”在命名和保存前拒绝，不向上传目录写入超限文件。
- 超限在解析中途发生时也显式关闭已创建的临时文件流，防止临时文件句柄遗留。测试自身的请求流也显式关闭。
- Flask 最低版本调整为 3.1，使用其[官方按请求设置大小上限的能力](https://flask.palletsprojects.com/en/stable/api/#flask.Request.max_content_length)。
- 新增 `tests/test_upload.py`：8 项测试通过，覆盖正常保存/下载、恰好 20MiB、多 1 字节、总请求过大、无 Content-Length 的终止流、临时文件关闭、原有格式错误，以及限制不泄漏到其他接口。测试在独立临时目录中运行，未使用项目数据库或上传目录。

## 10. 接续修正：连续拖动阻塞

用户确认 E1 的效果和功能暂未发现问题，但实际拖动滑条极其迟钝；同意若改造困难，可先继续功能、后续专项优化。检查后发现可先修复明确原因，本轮没有扩展 E2 范围。

### 原因与修改

- 原 `paint()` 将 Vue 响应式状态直接传入像素循环，循环内反复读取调整、兼容标记和滤镜，导致几百万次代理访问。此前直接调用渲染器的照片基准传入普通对象，遗漏了这条真实页面路径。现统一在像素处理入口读取一次参数，并对预览请求提交普通数据快照；原尺寸导出和兼容路径也受益。
- 增加本地 `editor-worker.js` / `preview-renderer.js`，通过 Worker 和 OffscreenCanvas 在后台处理预览；保留统一颜色算法及配方语义。后台每次只计算一个任务，并保留最后一个待处理状态，不排队计算全部中间数值。
- 拖动使用最长边 640 像素预览，松手/提交后恢复 1200。显示尺寸与构图独立于暂时的栅格分辨率，不出现照片缩小再放大的跳动；导出依然从源图按所选尺寸重建。
- 缓存同构图原图和几何结果，关闭已经使用或弃用的 ImageBitmap；替换照片时终止旧 Worker。旧结果不覆盖撤销、重置、新照片或最终参数；支持拖动期间显示仍有用的中间帧，最终帧必须与最新状态一致。

## 14. 2026-10-15：白平衡结果与滑条同步

用户发现自动曝光会移动滑条，而自动/取样白平衡改变图像后，色温/色调仍为 0。原实现将 RGB 增益保存在独立状态，两根滑条只代表附加偏移，面板未表达当前白平衡，构成反馈不一致。

- 新白平衡以两轴推导通道增益，归一化保持被选中中性色样本的原亮度；校正只处理一次，不同时叠加旧的色温/色调偏移。UI 相对单位不是开尔文。对于已受增益上限截断的极端取样，保留颜色比例并重新归一化，不承诺与旧截断结果的整体亮度完全相同。
- 为区分新旧温调语义，当前导出为版本 5，`white-balance.params.model='relative'` 标记统一控制。版本 1–4 及无此标记的旧增益/附加偏移保持原渲染，重新保存不改效果。旧的纯增益白平衡在面板派生显示两轴，第一次手调转入统一控制；旧增益与附加偏移均存在的复合配方仍保留其原始参数含义，重新自动/取样可进入统一控制。
