# 仓库维护约定

## 当前整理边界

2026-11-03 将根需求说明、阶段交接、日期修复日志与重复状态说明收敛为 `product/`、`research/`、`development/`、`operations/` 四类现行文档。历史提交可追溯旧方案和修复过程；不再在根 README 指向“新会话首读”或过时分支状态。

清理了没有当前调用方的原型图库匹配接口、未使用导入/辅助函数和孤立缩略图路径；保留旧配方读取、数据库幂等迁移、部署安装/恢复工具及素材许可声明。前端脚本存在跨文件全局引用和 CSS 层叠关系，不能只凭单文件扫描的“未使用”结果删代码。

测试按功能命名，去除已被当前流程替代的 E1 阶段布局检查。资料与私有配方检查纳入 `test_*.py` 自动发现；公共夹具不继承或重复运行另一套业务测试。浏览器检查使用临时服务、临时存储和合成账号，人工照片评审单独运行。

## 后续变更

- 产品行为改变时更新产品说明；接口/模块改变时更新架构；配置和安装改变时更新运维说明。
- 使用功能名称命名长期回归，临时诊断报告放 `test-results/`，不要再创建按日期堆积的交接文件。
- 影响配方的修改同步检查 `editor-core.js`、Worker、复用适配和后端 schema，并运行前后端往返。
- 保留数据库、用户照片、真实 `.env`、本地课件/素材；从 Git 移除文件不等于删除用户数据。
- `picture/` 与产品素材用途不同，测试需要的资源需有清晰来源；不依赖本机历史下载目录才能跑功能回归。
- 部署工具具有安装/恢复用途，其实际使用频率不决定是否可以删除。

验证命令、已执行结果与限制集中在[测试说明](testing.md)。
