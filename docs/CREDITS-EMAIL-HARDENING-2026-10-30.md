# PR #39 · 积分、邮箱与赞助流程修复

在原 `c8ca789` 实现上修复核验发现的问题，并合入主线截至 `dc372a8` 的修改密码、返回首页和过场更新。保留 Argon 的积分入口、赞助弹窗、收款码和 Gallery 美术。没有读取或提交真实配置、密钥、数据库或用户素材，没有重做社区数据导入。

## 认证与积分

- SMTP 缺失时邮箱接口返回服务不可用，不返回演示验证码，不签发可用于真实账号的测试凭据。验证码以随机盐加摘要保存，默认十分钟过期；仅最新一次成功投递的验证码有效。
- 服务端按邮箱／来源限制发送频率；验证码最多连续输错五次，并限制校验频率。绑定与登录用途、绑定发起账号分别校验。发送失败的验证码不可使用。
- 已验证邮箱通过数据库唯一索引约束，忽略大小写和首尾空格；绑定冲突明确提示，不覆盖其他账号。首次绑定奖励只发一次，邮箱登录不会反复增加奖励。邮箱和积分仍只在本人接口返回。
- AI 在外部请求前原子预留一积分，不跨外部网络持有数据库锁；失败或演示模式退款，成功完成才结算。异常中断留下的预留超过五分钟后，在查询积分或再次请求时自动退回且只退一次。
- 签到、绑定奖励和兑换采用事务与增量加分，避免覆盖其他并发操作。单次兑换资格检查、核销次数、到账和历史在同一事务内提交。
- 原体验口令 `LANDSCAPE2026` 保留每账号一次的规则；新用户十积分、签到三积分、首次验证邮箱五积分等产品额度保持。

## 赞助核验与投递

- 用户登记后给站长寄送确认页链接；**站长仍须先在支付宝核对实际收款**，系统没有接入支付宝支付回调。提交登记不代表已付款。
- 审批链接四十八小时有效，令牌只保存摘要。GET 只显示申请，POST 带确认凭证执行发码；仅接受界面列出的档位。成功后跳转回只读结果页，刷新不重发。
- 发码事务保证一申请一兑换码。兑换码从确认生成时起二十四小时有效、单次核销；寄送失败时保留原码，站长重新打开确认页即可重试投递，不生成第二枚。
- 重复登记同一笔待处理申请不会重复通知。通知失败明确返回失败状态，稍后重试复用申请。中断的发送可在等待两分钟后重试。
- 公开 Origin 与 `/landscape` 部署前缀分别处理，不给 `PUBLIC_ORIGIN` 添加路径。配置缺失时不使用任意外部 Host 生成审批链接。用户内容在邮件与页面中转义，审批页设置禁止脚本、禁止外部引用及禁止转发来源的响应头。
- SMTP 使用证书校验，不对用户输出原始 SMTP 异常。移除没有被代码使用的 `SPONSOR_SIGN_SECRET` 配置示例。

## 界面与配置

- 切换账号／退出后清除积分弹窗中的旧邮箱输入；旧账号的迟到响应不能覆盖新账号资料或积分。补上弹窗焦点管理，以及主站隐藏标签内容的规则。
- 服务器由 systemd 读取 `/etc/landscape/landscape.env`，不要在程序发布目录写 `.env`。用户已通过隐藏输入工具验证并保存 SMTP 授权码；新版本启动时加载，不需要再次提供授权码。
- 修复命令行发码工具，使其必须显式指定现有持久数据库（或 `LANDSCAPE_DB`），并在正确应用上下文中导入数据库模块。只读核验时不要运行发码命令。管理员确需手动发码可用：

```sh
sudo -u landscape /opt/landscape/current/.venv/bin/python /opt/landscape/current/scripts/generate_codes.py --database /var/lib/landscape/recipes.db --credits 50 --count 1
```

该命令会真实发码，输出仅供管理员使用，不能贴入公开 issue 或测试报告。
