# 产品需求与评审重点

本文件是整理后的现行产品基线，依据仓库截至 2026-11-03 的实现与项目组已确认的方向。目标用户和体验收益仍属于需要研究检验的假设，不能从功能已实现推导出用户已经满意。

## 定位与用户

平台服务风景照片编辑，以修图新手为主要用户，同时为摄影爱好者保留必要的精细控制。产品希望让用户通过手动参数、预设/社区样板、自然语言 AI 三条路径完成同一个编辑任务，并在这些路径间切换、比较和修正结果。

核心任务包括：改善曝光与颜色；借助样板探索风格；将“更通透、保留夕阳暖色”等意图变成可检查的调整；从他人配方学习；导出照片与复用自己的方案。

课堂展示以桌面浏览器为主，手机需要能显示并完成核心操作。专业 RAW 管理、商业人像精修、完整专业工作站不是当前目标。

## 体验原则

1. 三种编辑方式共用照片与历史，切换标签不丢失编辑。
2. 方案先预览、再明确应用；取消保留先前状态，应用后可撤销。
3. 原图不被覆盖，比较、撤销、复位和导出容易找到。
4. 新手先理解视觉结果，进阶参数按工具类别展开。
5. AI 给出简短目标与变化说明，不承诺当前引擎不支持的操作。
6. 清楚区分本地编辑、云端 AI 请求和社区发布的数据流。
7. 以完成任务、理解结果和控制修改的能力评估体验。

## 当前功能范围与验收

| 模块 | 当前范围 | 关键验收行为 |
| --- | --- | --- |
| 图片与画布 | JPG/PNG/WebP、单张 20MiB、单张 40MP；缩放、平移、适配、原图比较 | 无效输入不破坏已有照片；画布尺寸不意外限制原尺寸导出 |
| 状态与历史 | 单张参数、构图、局部调整、撤销/重做、组复位 | 一次拖动形成合理的历史动作，取消草稿不提交 |
| 手动工具 | 光线、颜色、白平衡、HSL、曲线、细节、暗角、局部蒙版与构图 | 参数和值一致、可继续手调、可复位及撤销；详见[编辑器说明](editor.md) |
| 预设 | 六类 18 款、经典滤镜、分类、搜索、本机收藏、强度 | 悬浮预览可恢复；切换替换风格；保留受保护字段和用户手调 |
| AI | 自然语言、1–3 个方案、变化说明、预览/应用、当前照片交流上下文 | 无效/失败/过期结果不改图；固定演示有明确标记；云端请求遵守账号与积分规则 |
| 配方复用 | 社区预览与复用、私有常用配方 | 拒绝未知版本和不支持操作；默认只复用全局调色，可主动选择作者构图与局部选区 |
| 多图与导出 | 最多 6 张、总文件 100MiB；各自参数/历史/导出选项；JPG/PNG、相框 PNG | 切图恢复各自状态，迟到 AI 不串图；关闭或返回首页有必要的编辑丢失提示 |
| 社区 | 浏览、搜索、分类、收藏、前后图、发布、作者主页 | 预览/取消不污染编辑；图对标记区分单图、人工配对和编辑器同构图配对 |
| 个人管理 | 资料与头像、密码、作品/收藏筛选、删除记录和七日内找回、私有配方 | 服务端按账号限定范围；其他用户不能修改本人数据；公开资料遵守隐私设置 |
| 偏好与积分 | 字号、动效、列数、排序、导出默认值、主页隐私；签到、邮箱验证、兑换和赞助登记 | 显示偏好保存在本机；公开隐私在服务端生效；新默认值不覆盖已有照片的独立导出设置 |

## 关键流程

**编辑照片：**打开示例或本地文件 → 选择手动、预设或 AI → 在画布比较效果 → 应用或取消 → 微调/撤销 → 导出照片或保存常用配方。

**复用社区配方：**浏览或搜索 → 查看作者说明与前后图 → 在自己的照片上预览 → 决定是否包含作者构图/局部选区 → 应用或取消 → 继续修改。

**分享作品：**编辑器准备完整配方与最长边 1600px 的同构图预览 → 社区填写名称、说明及分类 → 用户发布时上传。人工选择的前后图不能自动视为同源、同构图的可靠比较。

## 边界与待验证事项

- 编辑工作区只在当前页面内存中保存；云端常用配方保存参数快照，不保存完整可跨设备恢复的照片项目。
- AI 只提出当前工具能执行的参数，不做生成式修图；当前照片上下文不构成长久的个人偏好记忆。
- 自动曝光/白平衡与透视矫正属于传统统计或几何估计，允许拒绝不可靠结果，不能承诺适合所有照片。
- 暂未提供 RAW、镜头畸变校正、生成式换天/消除、AI 自动选区、批量同步导出、跨设备项目同步、关注关系或完整内容审核后台。
- 早期原型的 HSV 相似图库匹配没有现行界面调用，本次清理移除孤立接口；当前风格发现通过预设和社区浏览/搜索完成。
- 预设与算法依照本项目引擎调校，不承诺复现 Luminar、Lightroom 或商业 AI 产品的效果。
- 自动化主要在 Chromium 中运行；真实照片审美、连续交流质量、真实邮件投递、付费模型延迟/费用、弱设备与跨浏览器体验需要另行评估。

## 希望得到的项目意见

- 三条编辑路径是否围绕一个清楚的用户任务组织？对新手而言，功能层级和默认展开程度是否合适？
- 用户能否理解“预览、应用、取消、撤销”的区别，以及 AI 实际改变了什么？
- 预设、社区配方与 AI 是否各有可解释的价值，是否存在应当简化的重复入口？
- 会话照片、临时编辑与账号保存配方之间的关系是否清楚？
- 现有研究问题和任务脚本是否足以评估易用性、控制感与信任？应优先补充什么证据？

相关访谈和观察方法见[研究计划](../research/plan.md)。
