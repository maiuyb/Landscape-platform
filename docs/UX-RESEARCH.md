# 用户体验调研与竞品评估计划

版本：0.1  
目的：在扩大开发范围前，验证风景照片编辑用户的实际任务、困难和产品价值路径。

## 1. 研究目标

1. 发现用户修风景照片的真实流程、常见输入输出和现有替代工具。
2. 比较手动工具、样板风格和 AI 对话三种路径的发现性、控制感、结果质量和信任。
3. 找出样板选择最需要的信息：示例图、适用场景、参数、强度、作者、使用反馈等。
4. 验证经验用户需要哪些参数，以及哪些专业功能可暂缓。
5. 验证用户对图片上传、云端 AI、公开分享和配方复用的预期。

## 2. 建议参与者

若项目组采纳个人用户画像建议，首轮可招募 6–10 人，以新手为主、摄影爱好者为辅，用经验和行为分层，而非只按年龄分组。专业摄影师不作为主要目标样本，可选 1 人补充专家意见：

- 2–3 位较少手动修图、依赖手机自动效果或滤镜的用户。
- 2–3 位经常拍摄并自己调整照片的爱好者。
- 2–3 位有 Lightroom、像素蛋糕或类似工具经验的人。
- 如团队希望验证社区方向，再加入 1–2 位经常分享照片/预设的人。

招募时确认最近一次风景照片修图经历、常用设备和工具。尽量请参与者拿一张自己熟悉的照片，或使用统一测试照片并允许其自带照片。不要只询问“你喜欢哪个界面”。

## 3. 竞品/参考产品与取样重点

### 3.1 Fotor：最接近当前轻量网页定位的直接参照

观察上传后首屏、基础调整与滤镜入口、自动增强的可见性、预览和导出反馈。记录功能入口是否更像“修照片”而非“做设计”。官方页面主打在线调色、滤镜、裁切、一键增强和背景处理。详见 [Fotor 网页编辑器](https://www.fotor.com/) 与 [功能页](https://www.fotor.com/features/)。

### 3.2 Canva：快速出图与设计上下文

观察其如何把单张照片编辑接入设计项目、模板和分享流程。用于理解导入和输出如何简化；不作为风景调色面板或专业工具深度的主参照。详见 [Canva Photo Editor](https://www.canva.com/photo-editor/)。

### 3.3 Lightroom：熟练控制、预设学习与复用

观察曝光/颜色工具的分组、预设应用后的强度/参数控制、复制编辑、编辑版本、Discover/Remix 的学习与分享流程。Adobe 说明 Lightroom Discover 提供可下载编辑预设，并可按用户照片特征推荐相似作品的编辑；这为“样板图 + 可复用设置 + 适配用户照片”提供了直接参考。[推荐预设与 Remix FAQ](https://helpx.adobe.com/lightroom/desktop/using/remix-recommended-presets-faq.html)、[编辑和复制设置](https://helpx.adobe.com/lightroom/desktop/edit-photos/edit-photos.html)。

### 3.4 像素蛋糕：样片仿色和摄影工作流

观察 AI 追色、预设选择、实时预览、批量处理和手动微调如何组合。官方信息显示其重心是商业人像/摄影工作流，并有 AI 仿色和户外风光样片色调等能力。不要直接假设其“开放式聊天 AI”已经得到验证；需让熟悉该产品的摄影用户演示具体操作或提供截图/录屏，再判断对话路径是否存在。[官方功能页](https://www.pixcakes.com/)、[工作区功能说明](https://wiki.pixcakeai.com/guide/9379.html)、[iOS 产品页](https://apps.apple.com/cn/app/%E5%83%8F%E7%B4%A0%E8%9B%8B%E7%B3%95-%E4%B8%93%E4%B8%9A%E7%BA%A7ai%E4%BF%AE%E5%9B%BE%E8%BD%AF%E4%BB%B6/id6743614900)。

### 3.5 Snapseed：低门槛移动编辑和可逆操作

观察工具选择、滤镜与手动微调关系、局部选择、撤销/重做、如何让用户理解编辑顺序。适合做手机端快速编辑参考，不直接代表桌面网页布局。[Google Play](https://play.google.com/store/apps/details?id=com.niksoftware.snapseed)、[Apple App Store](https://apps.apple.com/us/app/snapseed/id439438619)、[官方工具说明](https://support.google.com/snapseed/answer/6183571?hl=zh-Hans)。

### 3.6 开源参照：只借鉴局部交互或实现模型

- [miniPaint 在线体验](https://viliusle.github.io/miniPaint/) / [GitHub README](https://github.com/viliusle/miniPaint)：纯浏览器图像处理，README 说明文件在浏览器处理、支持撤销、裁剪、颜色调整、滤镜和多种导入导出。因为功能面很宽且界面接近通用图像编辑器，用于理解开源画布、历史和本地处理，不作为轻量产品复杂度样板。
- [darktable 功能与工作流文档](https://www.darktable.org/about/features/) / [GitHub](https://github.com/darktable-org/darktable)：专业摄影流程、非破坏性处理、历史与 XMP sidecar 的参照。复杂度高，主要观察如何表达编辑历史、图像来源和导出。
- [RawTherapee 官方文档](https://rawpedia.rawtherapee.com/The_Image_Editor_Tab) / [GitHub](https://github.com/Beep6581/RawTherapee)：提供 RAW 调整和处理配置文件；适合把成熟摄影控制映射为用户能理解的类别，同时关注复杂度边界。

### 3.7 建议优先级

第一轮深入体验：**Fotor、Lightroom、像素蛋糕、Snapseed**。  
第二轮局部观察：Canva 的快速上传/导出；miniPaint 的浏览器编辑/撤销；darktable 或 RawTherapee 的熟练用户控制面板。

## 4. 竞品体验记录表

每个产品至少记录下列内容，并保留日期、设备、版本/网页状态：

| 观察项 | 记录问题 |
|---|---|
| 首次进入 | 用户第一眼认为产品能做什么？第一步是否明显？是否必须注册？ |
| 导入 | 支持什么来源和格式？上传后如何给反馈？大图等待时发生什么？ |
| 当前编辑状态 | 原图、预览和已编辑结果是否容易区分？是否显示文件名或修改状态？ |
| 控制入口 | 参数如何命名、分组和展开？新手如何理解？熟练用户如何快速定位？ |
| 预设/样片 | 看见什么信息后用户敢点击？能否先预览自己的照片？可否改变强度？ |
| AI/自动增强 | 用户知道发生了什么吗？是否有解释、预览、确认、重试和撤销？ |
| 可逆性 | 原图保护、撤销/重做、对比和版本恢复是否明显？ |
| 输出 | 导出格式/质量/尺寸是否清晰？下载成功与失败反馈如何？ |
| 信任与商业化 | 何时要求登录/付费？哪些照片会上传？免费与付费能力如何提示？ |
| 情绪与控制感 | 用户何时犹豫、惊喜、困惑或不信任？引用原话，不替用户解释。 |

## 5. 访谈提纲

建议 30–45 分钟。先询问真实经历，再演示原型。

1. 最近一次你修风景照片是什么时候？当时为什么要修？照片最后用在哪里？
2. 请描述或演示从拍摄文件到最终照片的过程。中间用了哪些工具？
3. 哪些环节最费时间、最难决定或最容易返工？最近一次遇到什么具体例子？
4. 你怎样判断一张风景照片已经“修到位”？哪些效果你会避免？
5. 你常用哪些参数或功能？哪些工具你知道存在但基本不碰？为什么？
6. 你会如何找一个想模仿的色调？看样片、教程、预设、朋友设置还是 AI？
7. 使用预设时你希望看见什么信息？你是否会修改预设？会担心什么？
8. 如果能用一句话描述想要的结果，AI 应该先问什么、先展示什么、何时允许改图？
9. 哪些情况下你不愿把照片交给在线服务处理？是否会接受缩略图发送给 AI？
10. 你会不会保存/分享自己调出的方案？什么内容你愿意公开？

避免用“如果我们做一个 AI 功能你会不会用”这类诱导性假设题。追问具体最近行为和实际取舍。

## 6. 可用性任务脚本

给参与者一张未经处理的风景图，并在必要时允许使用自带图。主持人只读任务，不教具体按钮位置。

### 任务 A：从样板开始

“你想把这张阴天的山景修得更清透，但不要变成过饱和。请找到一个合适的起点，试到你觉得满意，然后导出。”

观察：是否理解卡片、能否预览到自己的照片、是否发现强度控制、能否看原图、何时认为结果达成。

### 任务 B：手动控制

“天空有些亮，前景偏暗。请在不改变照片构图的情况下尽量改善它，并告诉我你觉得改了什么。”

观察：控制项能否发现、名称是否匹配预期、参数结果是否可理解、是否需要直方图或解释。

### 任务 C：AI 快捷建议与对话迭代

“请让夕阳色彩更有层次，但保留自然感。先让系统给你一个可预览的建议，再决定是否接受。接受后请继续要求它弱一点。”

观察：用户能否区分快捷推荐和自由描述、AI 是否理解意图、预览与确认是否清晰、解释是否有帮助、二轮修改是否保留上下文、用户是否知道如何撤销。

### 任务 D：恢复与输出

“比较现在和原图；如果不满意，回到上一版本。然后导出适合网页分享的文件。”

观察：对比方式是否易用、回退范围是否明确、导出选项是否让人困惑、是否担忧源图被覆盖。

## 7. 记录和分析方法

- 取得同意后录屏/录音；敏感照片不保存到调研材料，使用虚构或参与者明确授权的测试图。
- 记录完成/未完成、时间、首次点击、误操作、主持人提示、用户原话和任务后评分。
- 每项任务结束后使用 1–7 分询问：结果满意度、操作容易度、掌控感、对结果的信任度；另问“你最不确定的是什么？”
- 归纳主题时区分直接观察、参与者解释、研究员推断和产品假设；每个需求至少链接一条证据或标记为待验证。
- 小样本测试用于发现交互问题，不用于宣称统计显著或代表全部市场。

## 8. 测试后决策规则

- 若样板路径更快但用户无法解释结果，增加参数摘要或效果说明再测。
- 若熟练用户找不到专业控件，先调整信息架构/搜索，再讨论添加更多控件。
- 若 AI 用户需要多轮纠正，优先提升上下文和局部调整表达，不先增加模型数量。
- 若大多数用户不愿上传图片，探索本地处理、缩略图最小化或先使用不带图像的意图对话。
- 若用户不需要社区分享，先把资源投入样板质量和导出，而不是搭建点赞/关注系统。
- 若任务成功但结果满意度低，回到调色质量、图像适配和示例图，而非只修改按钮布局。

## 9. 公开资料的边界

官方功能页适合确认产品公开宣传和功能入口，帮助中心适合确认具体操作路径，开源项目文档适合确认工作流和实现约束。它们无法替代目标用户访谈，也不能证明某个功能有效。像素蛋糕、Lightroom 等产品对外宣传的效果数字不作为本项目性能基准；应用商店评分/评价可作为发现问题线索，但不作为无偏代表性研究样本。
