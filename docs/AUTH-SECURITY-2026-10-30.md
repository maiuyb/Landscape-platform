# 注册验证与登录防刷 · 2026-10-30

新账号必须完成邮箱验证后创建。用户名／密码注册先填写邮箱并完成图形验证、获取邮件验证码；邮箱验证码免密入口也保留。两条注册路径共用成功创建额度。初始 10 积分加首次验证 5 积分的规则不变。新账号密码 8–128 位，旧账号继续接受原密码。

旧账号及会话、作品、积分保留，不强制重新注册，不要求每次登录都收邮件，也不额外限制旧账号的 AI 使用。旧 SHA-256 密码在成功登录时通过条件更新迁移为带盐 PBKDF2-SHA256（600,000 次），修改密码也兼容旧格式并写入新哈希。用户中心提示未验证账号补充绑定邮箱。

## 默认限额与挑战

- 服务端持久化原子计数，业务失败不回滚请求次数；只使用实际客户端地址，线上代理覆盖转发头，直连不信任伪造 X-Forwarded-For。
- 认证接口：每 IP 每 10 分钟 300 次，站点每 10 分钟 1,800 次。登录：每 IP 每分钟 30 次、每 10 分钟 100 次；退出：每分钟 30 次。注册请求及成功创建分别限制每小时 10 次、每天 30 次。这是小规模默认值，共用校园出口人数增加时需观察并调整。
- 登录失败按来源＋账号及账号分别累计。15 分钟内失败 5 次后要求图片验证；同一来源对同一账号失败 10 次后冷却 60 秒。不会永久锁号，其他来源仍可通过图形验证登录。
- 服务端图片验证 3 分钟有效，一次使用，绑定来源和用途，只存加盐摘要。获取图片也限流。它提高低成本脚本的成本，不能抵御所有 OCR 或分布式攻击。
- 未登录发邮件前要求图形验证；已登录绑定不增加图片步骤。保留原有邮箱／IP 发送与校验额度、10 分钟邮件有效期、最多 5 次输错；新增全站每小时 100、每天 500 封验证码邮件预算。
- 认证请求体上限 16KiB，修改密码也限制请求体及频率。限流返回 429 和 Retry-After。

## HTTPS 与入口限流

`deploy/enable-auth-https.py` **需要 sudo 单独运行，main 自动部署不会激活它**。自动定位既有 HTTP 站点，将相关配置备份到 root 私有目录；使用 Certbot 5.4+ 申请六天 IP 证书，验证公网 HTTPS 后再切换 PUBLIC_ORIGIN 与 HTTP 跳转。失败恢复原配置，不输出私钥或 SMTP 内容。

认证路径增加每 IP 2 次／秒、全站 10 次／秒的 Nginx 限流，允许有限突发，返回 JSON 429。HTTP 根站保留，ACME 使用独立路径，不启用会把整个 IP 根站强制切到 HTTPS 的 HSTS。systemd 每六小时检查续期并在证书更新后检查、重载 Nginx。

助手上传并核对脚本后，由管理员执行：

```sh
sudo python3 /home/ezio/hmi-enable-auth-https-20261030.py
```

若 ECS 安全组未放行 TCP 443，放行后重试。运行状态在 `/opt/landscape/https-status.json`，只能以实际状态和公网验证判定成功。切换 HTTPS 前先保存照片；新 Origin 不共享旧站浏览器存储，需要重新登录。

依据：[Let's Encrypt IP 证书与 Certbot 官方说明](https://letsencrypt.org/2026/03/11/shorter-certs-certbot)。
