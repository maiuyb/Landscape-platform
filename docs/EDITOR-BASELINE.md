版本：1.2（交互反馈与 E2 实现接续）

日期：2026-10-14（中国标准时间）

状态：用户已确认以 Luminar 为主要参照，先确定编辑功能基线；本文细化功能、分批顺序和验收要求。参数范围、步长与算法细节是可在效果评估后调整的实现初值。

本文补充 [PRD.md](PRD.md)，取代此前“只实现原始需求规格说明书中的 8 个调色参数”的限制。首次整理仅更新文档；随后用户授权开发，并在确认性能修正后要求调整交互、加入自动曝光/白平衡及取样笔，继续开发路线。当前 E1/E2 已本地实现，E3 中的裁剪直接操作已提前交付；锐化、降噪与拉直尚未实现。证据见 [DEVELOPMENT-STATUS.md](DEVELOPMENT-STATUS.md) 第 11 节。

## 1. 参照依据与产品边界

- **Luminar Neo：**主要参照工具分组、参数语义、渐进展开和样板目录。界面依据用户提供的本机 1.22.1 四张截图；官方资料仅用于核对工具含义，可能涵盖更新版本，不自动纳入新增功能。
- **Fotor：**补充网页操作、展开后的参数控制、裁剪与应用/取消流程；后续重点观察 AI 入口和调用反馈。已观察基础编辑的 12 个展开面板，未完成全部 AI 功能、会员限制或效果质量验证。
- **Lightroom：**遇到效果实现问题时补充技术参考。**像素蛋糕：**仅作 AI 能力边界参考，不以其商业精修效果作为 Qwen 的验收标准。

目标仍是新手为主、摄影爱好者为辅的风景照片网页编辑器。支持 JPG、PNG、WebP 导入，单张最大 20MiB；PC 为主，手机核心路径可用。当前编辑状态只保留在页面内存中，刷新后不恢复。

采用 Luminar 的控制思路，自行实现浏览器图像处理。相同名称或数值不承诺相同画质；已截断为纯白/纯黑的像素不能通过滑块恢复真实细节。RAW、镜头数据库、专业色彩管理和 AI 生成效果不纳入这套基线。

## 3. 工作区与通用交互

PC 采用大画布和右侧编辑面板，视觉以安静的深色中性背景为方向。右侧按以下顺序组织：**光线 → 颜色 → 曲线 → 细节 → 构图**。样板可切换右侧内容，AI 打开时仍能访问参数；三者共享照片和编辑状态。

默认展开光线，其他组折叠；颜色展开后先显示基础颜色，HSL 在组内单独展开。曲线与细节的进阶控制按需展开。保留各组展开状态和滚动位置，不强制用户关闭另一组。无需照片目录、评分、购买入口或会员提示。

菜单选择：用户指出 Luminar 的基础颜色属于“开发”，一级“颜色”为 HSL，并允许保留本项目组织方式。本次继续采用任务分类，基础颜色和 HSL 共用“颜色”组，避免重复饱和度与自然饱和度入口；曲线独立。一级箭头统一，二级用不同标记。尚未实现的细节工具不显示空菜单。

1. 滑块旁提供可编辑数值、单位/范围、可见单项复位和简短含义说明；双击名称也可复位，但不依赖用户发现此操作。支持键盘和触摸操作。彩色轨道辅助解释变化方向，同时保留文字标签。
2. 所有效果默认中性。单项、分组和整体重置均可撤销；分组重置仅清除该组效果，整体重置还原构图与全部效果。
3. 连续拖动或一次数值输入形成一条历史；切换 HSL 模式、曲线通道、面板或对比方式不形成编辑历史。
4. 没有照片时解释导入入口；无效输入不提交，给出合法范围。锐化/降噪未启用时可禁用依赖控制，并说明启用条件。
5. 手动调色即时预览。基础滤镜悬浮或键盘聚焦即预览并显示说明，离开恢复，点击直接应用并允许立即切换，撤销恢复；触摸点击直接应用。构图、完整配方、团队样板和 AI 继续采用暂存预览及“应用 / 取消”；取消恢复进入预览前的完整状态，应用按钮标为“应用到照片”。
6. 比较沿用“原图 · 同构图”：两侧裁剪/旋转一致，仅比较图像效果。构图工具另显示保留区域和边界。
7. 预览允许降低计算分辨率，输出仍从源图重建；新增工具不得导致导出尺寸受工作预览限制。

## 4. 第一批 E1：光线、基础颜色与参数一致性

### 4.1 光线

| 控制 | 建议范围 / 步长 / 默认 | 产品语义 |
|---|---|---|
| 曝光 | −3～+3 EV / 0.05 / 0 | 整体曝光；正值更亮，负值更暗。显示两位小数和 EV |
| 对比度 | −100～100 / 1 / 0 | 增强或减弱明暗差异；先提供可靠的普通对比度 |
| 高光 | −100～100 / 1 / 0 | 调整亮部；正值提亮，负值压暗 |
| 阴影 | −100～100 / 1 / 0 | 调整暗部；正值提亮，负值压暗 |
| 白色 | −100～100 / 1 / 0 | 调整白点和最亮端，与覆盖较宽亮部的高光控制有所区别 |
| 黑色 | −100～100 / 1 / 0 | 调整黑点和最暗端；正值抬黑，负值加深 |
| 亮度（更多控制） | −100～100 / 1 / 0 | 保留现有整体亮度调整与旧配方兼容，避免默认与曝光并列争夺主要入口 |

光线组内先列曝光、对比度、高光、阴影，白色/黑色作为相邻子组。Luminar 截图称“智能对比”，本项目先标为“对比度”；自适应算法通过照片评估后再决定是否升级名称。

上述明暗控制方向依据 [Skylum Develop 工具说明](https://support.skylum.com/editing-tools/essential-tools/develop-raw-develop)；范围和步长为本项目建议值，不照搬 Luminar 内部参数。

### 4.2 基础颜色

| 控制 | 建议范围 / 步长 / 默认 | 产品语义 |
|---|---|---|
| 色温 | −100～100 / 1 / 0 | 负值偏冷，正值偏暖；当前普通图片采用相对调整，不显示虚假的开尔文温度 |
| 色调 | −100～100 / 1 / 0 | 负值偏绿，正值偏洋红 |
| 饱和度 | −100～100 / 1 / 0 | 调整整体色彩强度 |
| 自然饱和度（鲜艳度） | −100～100 / 1 / 0 | 优先影响较淡颜色，对已经鲜艳的颜色减少增强；不能仅复制饱和度算法 |

界面主标签统一为“自然饱和度”，说明中保留“鲜艳度 / Vibrance”，便于用户对应截图和常见术语。其与饱和度的区别参考 [Skylum Color 工具说明](https://support.skylum.com/editing-tools/essential-tools/color)。

### 4.3 E1 完成条件

- 新增白色、黑色、自然饱和度在中性设置下不改变图像，在渐变和真实照片上表现出各自作用范围；不出现明显色带、断层或普遍色偏。
- 曝光具有明确 EV 语义；高光与阴影、白色、黑色的正负方向一致。实际效果应可区分曝光、亮度、端点与分区明暗调整。
- 右侧分组和数值输入可用；新增状态可撤销、复位、预览、导出和重新读取配方。
- 旧配方兼容按第 8 节验证，不能直接改符号或单位而改变历史配方含义。

### 4.4 后续反馈新增：自动调整与取样

自动曝光采用亮度直方图中位数估计，并用高亮分位数限制增益，结果限制在 ±1.5 EV；写入曝光参数，支持撤销。自动白平衡采用低饱和像素的灰世界估计，优先近中性区域，排除过暗/截断区域并约束通道增益；候选不足时提示用户取样或手调，不改变原设置。这是普通图片上的保守实现，不能恢复截断细节，也不能判断日落等暖色是否有意保留。[OpenCV GrayworldWB](https://docs.opencv.org/4.x/d7/d71/classcv_1_1xphoto_1_1GrayworldWB.html) 提供灰世界及按饱和度选像素的技术参考。

白平衡取样笔让用户在照片中选择应呈中性白/灰的区域，平均局部像素后求通道增益；过暗、透明或不可靠的截断区域拒绝取样。自动/取样白平衡清零旧色温与色调，以免重复叠加，随后仍可手调；所有参数和模式均可撤销/重做和保存配方。图像需有可判断的中性色，彩色物体不能作为可靠白点。

## 5. 第二批 E2：HSL、曲线与直方图

### 5.1 八色 HSL

采用用户第二张截图的结构：下拉选择 **色相 / 饱和度 / 亮度**，下方固定显示 **红、橙、黄、绿、青、蓝、紫、洋红** 八个色段。每段保存三个独立值，总计 24 项，建议均为 −100～100，步长 1，默认 0。

- 切换下拉项只改变显示，保留其他模式的设置；提供当前色段复位和整个 HSL 复位。
- 色相改变所选颜色的偏向，饱和度改变其强度，亮度改变其明暗。轨道展示相应方向；色相滑块的实际角度映射由照片效果评估确定。
- 色段间平滑过渡，红色在色环首尾连续；低饱和区域降低色相调整影响，避免灰色被无意染色。色段范围以原始色相判定，避免一次处理把像素反复归入下一色段。
- HSL 是按颜色选择，不是空间蒙版。例如修改蓝色会同时影响蓝天、蓝水和其他蓝色物体；AI 不得将其描述为“只改天空”。

HSL 模式含义依据 [Skylum Color 工具说明](https://support.skylum.com/editing-tools/essential-tools/color)，八色布局依据用户截图。本项目不在此批加入全局色相轮转或自动去色偏滑块。

### 5.2 曲线

提供整体、红、绿、蓝四个通道，选择器带文字标识。横轴输入暗→亮，纵轴输出暗→亮；上移控制点使相应色阶更亮，下移更暗。默认对角直线为中性。

支持添加、拖动、选中和删除中间控制点，端点可移动并单独复位；控制点按横坐标排序，防止重合导致非法插值。建议每通道最多 10 个点（含端点），并提供选中点的数值输入与键盘调整。保留当前通道和全部曲线复位。

曲线之间采用固定、可复现的处理顺序；预览、输出和配方恢复一致。非线性插值需约束过冲，输出保持合法范围。底部额外的黑/中/白场手柄不列入 E2 必做，避免与光线组重复控制。

E2 实现采用形状保持的 PCHIP 插值，每通道最多 10 点；端点横坐标固定在输入两端、纵坐标可调。选中点支持 0–255 输入、方向键（Shift 加大步长）和中间点删除。处理顺序为白平衡增益 → 光线/基础颜色 → HSL → 整体/R/G/B 曲线 → 基础滤镜，预览和原尺寸输出共用。插值方法参考 [SciPy PchipInterpolator](https://docs.scipy.org/doc/scipy/reference/generated/scipy.interpolate.PchipInterpolator.html)，自行用 JavaScript 实现。

### 5.3 直方图与 E2 完成条件

提供亮度及 RGB 分布，随当前编辑预览更新，可使用降采样数据并合并更新。直方图说明反映预览的分布，不冒充 RAW 传感器数据；图表本身不产生编辑历史。

E2 验收包括：24 项 HSL 切换后不丢失、色段边界连续、灰阶保持中性；四通道曲线独立保存、对角线无效果、复位与撤销正确；拖动曲线及滑块时直方图与画布最终一致；配方往返和原尺寸输出覆盖新工具。

## 6. 第三批 E3：细节与构图

### 6.1 锐化与降噪

| 控制 | 建议范围 / 默认 | 要求 |
|---|---|---|
| 锐化 | 0～100 / 0 | 增强边缘细节；强度为 0 时完全中性 |
| 锐化半径 | 0.5～3.0 源图像素 / 1.0 | 控制边缘影响宽度；预览需考虑源图与预览缩放差异 |
| 锐化边缘保护 | 0～100 / 0 | 数值越高越偏向明显边缘，减少天空等平坦区域被过度锐化；提示对应 Luminar 的“锐化蒙版” |
| 明度降噪 | 0～100 / 0 | 降低亮度噪点，同时保护边缘和纹理 |
| 颜色降噪 | 0～100 / 0 | 降低杂色噪点，避免整体去饱和或颜色渗漏 |

先实现这五项。截图中的细节保护、细节遮罩和额外降噪强度作为后续候选，不先堆出无可靠作用的滑块。边缘保护由算法计算，和用户绘制的局部蒙版区分；不要求实现笔刷/区域选择。

提供 100% 查看提示和入口，评估细节需覆盖真实照片局部，不能只靠适配画布的缩略图。处理顺序明确并保存版本，原则上降噪先于最终锐化；工作预览与输出按同一效果定义处理，性能优化不能偷偷取消输出效果。

### 6.2 构图

- 裁剪框支持角点/边缘手柄和框内移动，边界不能越出可裁剪区域；显示外部遮罩、保留尺寸与可开关的三分线。
- 提供自由、原图比例、1:1、3:2、4:3、16:9 及竖向对应比例，支持比例锁定和宽高输入；尺寸以源图像素解释，不把屏幕显示像素当作输出尺寸。
- 拉直滑块建议 −45°～45°，带数值输入；保留现有 90° 旋转、自由角度旋转及水平/垂直翻转。连续旋转不得反复重采样源图。
- 构图采用“应用 / 取消”，提交一次历史。拉直可选择自动裁去空白或保留空白，并在提交前预览输出范围；保留空白时 PNG 透明、JPG 白色填充，延续现有说明。

### 6.3 E3 完成条件

对高 ISO、树叶/草地、建筑边缘和天空区域检查锐化光晕、噪点放大、涂抹和杂色处理。裁剪尺寸、锁定比例、拉直后的边界、取消/撤销以及输出像素一致；PC 可直接操作，手机也能完成裁剪与应用。

## 7. 工具稳定后：团队样板与 AI

本机 Luminar 安装目录的 `Data/PresetPacks/Collections` 中已只读检查到 22 个内置集合配置，样板目录包含 `template.lmps` JSON、缩略图和部分外部资源。截图中的轻快风景、阴天、日落、都市灯光有对应集合。这里能读取组织结构与效果参数，不能获得 Luminar 的私有处理引擎。

研究结果用于策划自己的风景样板：集合 → 风格卡片 → 适用场景与前后图 → 当前照片预览 → 强度 → 应用/取消 → 参数微调。沿用 [PRD LOOK-01–06](PRD.md)；应用时更新配方明确列出的参数，保留未列出的参数及当前构图，界面说明此规则。取消恢复之前的状态，应用形成一条历史。该规则是本项目选择，不照搬 [Luminar 应用预设会覆盖调整的行为](https://support.skylum.com/presets/browsing-and-applying-presets)。

本阶段不建设通用 Luminar 预设导入器。研究时区分：

| 预设内容 | 本项目处理原则 |
|---|---|
| 曝光、颜色、HSL 等有对应工具的值 | 理解其目标后用本项目算法重新调校，不能原数值照搬并承诺等效 |
| LUT、天空图片、缩略图等外部资源 | 记录依赖及来源；发布素材使用团队生成或可使用的资源 |
| AI 结构、天空增强、雾气、RAW 白平衡、私有滤镜 | 标记为未支持；不静默丢弃后宣称完整复现 |

Qwen 先输出受支持参数和变化摘要，经范围校验后进入同一预览/应用流程。仅开放已实现并验证的工具；不让模型调用任意脚本，也不把整体色调修改包装成局部修图。真实模型、多轮交互和样板数量在工具稳定后单独评估。

## 8. 状态、配方与兼容要求

新工具须接入统一参数状态、历史、分组复位、样板强度、AI 校验、配方和输出，不能只增加界面控件。曲线点、HSL 24 项和细节参数都应可序列化；未知操作明确提示，合法的已知部分仍可预览。

E1 前的本地配方为版本 1，曝光保存 −100～100，处理倍率是 `2^(value/50)`；高光正值压暗。E1 新导出采用版本 2，改曝光单位和高光符号，并实施显式迁移：

- 旧曝光按 `value / 50` 转为 EV；旧高光需转换符号。
- 转换单位/符号只保证语义对应；若同时升级算法，必须用旧版渲染或迁移效果验证处理视觉差异，不能宣称数值转换自然保证逐像素相同。
- 不修改版本 1 的既有含义；导入老配方时说明兼容处理，保留旧文件。新功能缺省为中性，不能凭空新增效果。
- 参数有限值、范围、曲线点和几何边界在导入/AI 入口统一校验。拒绝不支持的新版本时给出清楚提示。
- 社区分支的配方协议在后续接入时单独核对，不假设现有社区 API 已支持这些新字段。

E1 实现使用 `rendering.legacyTone` 保留旧版高光/阴影响应，手动改变旧版高光或阴影时，仅该项切换新版平滑响应，界面提示且可撤销。E2 当前导出升级到版本 3：增加 `white-balance`（通道增益和模式）、八个 `hsl` 操作（三项值）及四个 `curve` 操作（控制点）；继续导入版本 1/2，新字段缺省中性，保留 `rendering.legacyTone`。旧后端/AI 无版本列表仍按版本 1 读取；新版方案须保留完整版本封装。无效新操作提示并忽略，合法已知部分仍可预览。

## 10. 实施顺序与质量验收

| 顺序 | 交付 | 进入下一批的条件 |
|---|---|---|
| E1 | 光线/颜色分组、数值输入、白色/黑色/自然饱和度、曝光/高光统一及旧配方兼容 | 真实照片效果、状态恢复和输出验证通过 |
| E2 | 八色 HSL、整体/R/G/B 曲线、直方图 | 颜色边界、曲线编辑、配方往返及预览性能验证通过 |
| E3 | 锐化/降噪、裁剪手柄/尺寸/比例、拉直 | 细节质量、构图几何、手机核心操作及原尺寸输出验证通过 |
| 后续 | 团队样板、真实 Qwen 建议，再核对社区接入 | 基于支持工具形成可解释方案；另行确定接入范围 |

当前进度：E1/E2 已本地完成；裁剪手柄、移动、尺寸/比例已提前交付。下一批 E3 专注细节和拉直。每批的工程/照片检查通过后提供代表结果供反馈，不要求用户承担自动化检查。

每批均用真实风景照片验证效果，至少覆盖逆光、亮天空/雪景、深阴影、绿色植被、日落、城市夜景、细纹理和高噪点；一张照片可以覆盖多种场景。记录素材来源、源图尺寸、参数和前后结果，避免只有自绘色块通过的结论。

共同验收要求：

1. 中性参数不改变解码后的像素（除明确的几何/输出尺寸变化）；PNG 用像素对比，JPG 考虑有损压缩，不能要求文件字节相同。
2. 代表照片无明显色阶断层、异常色偏、透明边缘污染；极值的截断或过强效果应可理解、可复位。
3. 所有新操作可撤销/重做、分组复位、同构图对比、样板/AI 预览取消；刷新生命周期与现有说明一致。
4. 原尺寸输出、不同输出比例和配方重新导入保持预期效果；测试包含旧版配方和不合法参数。
5. 静止时最长边 1200 像素预览，拖动时可用 640 像素后台预览并在松手恢复，显示尺寸不随分辨率跳动。暂以常见滑块 200ms 内反馈为目标，另需检查持续拖动的输入响应、主线程阻塞和最后状态一致性；单次渲染器计时不代表交互验收。曲线、直方图和细节分别测量，记录浏览器、设备、图像尺寸和数据，不能沿用旧测试宣称已达标。
6. 工程检查与照片效果检查由开发者完成，不要求用户每批手动测试。审美或操作取舍通过少量代表性结果征求反馈；正式无指导任务测试另行组织，验证查找、理解、复位和导出。发现严重理解问题时先调整交互，再扩展工具。
